# Phone hooks

Sources live in `aesop-xi/hooks/`. Live copies are in `~/.claude/hooks/` and `~/.config/git/hooks/`. Rules registry: `~/.claude/ENFORCEMENTS.md`.

| File | Event | What it does |
|---|---|---|
| `git-hooks/dispatch` (+ symlinks) | git, every repo (global hooksPath `~/.config/git/hooks`) | gitleaks on pre-commit / pre-push. A secret blocks it. Then runs the repo's own hook. Exceptions only through the repo's `.gitleaksignore`. |
| `checkin-gate.sh` | PreToolUse `*` | after RESUME is read: no changes until the operator checks in with `/ok` / `/ok 1,3` / `/ok 1-4` / `/ok all` / `/defer 2` / `/reject 2` / `/write 2 <changed instruction>` / `/write <new item>` (`#` forms too). Judges Bash by the commands that run, not text inside quotes or heredocs (obs 0042); interpreter runs (`python`, `node`, `bash <file>`) count as changes (obs 0044). Reading, searching, task tools, StructuredOutput, AskUserQuestion, read-only Bash, the observer checkpoint, `resume-item plan` and Explore/Plan subagents stay allowed. Only for sessions started with the RESUME snapshot |
| `secret-guard.sh` | PreToolUse `Bash\|Read` | refuses printing secret files unless the values are redacted; refuses git hook skipping or hooksPath changes |
| `resume-gate.sh` | PreToolUse `*` | no tool runs until RESUME.md (the repo's, else the vault's) has been read. Afterwards it records the opening-sequence reads (AGENTS.md, PENDING.md, MEMORY.md, WRAP-UP.md) in `state/opening-<sid>.tsv`, re-checks RESUME's hash on every call and blocks once when another session rewrote it (obs 0044; a re-read refreshes the snapshot, the old one is kept as `.snap.prev.md`), and reports RESUME's own date: missing, future, or older than `AESOP_RESUME_MAX_AGE_DAYS` (14) |
| `enforce-gate.sh` | PreToolUse `*` | no tool runs until this prompt's ENFORCEMENTS requirements are met |
| `branch-current-gate.sh` | PreToolUse `Bash\|Edit\|Write` | no edits or `git commit` in a c10vis-poem repo whose branch doesn't contain the latest `origin/<default>` (fetches once per repo per session). Fix: start a worktree from current main. Vault exempt (GitSync) |
| `sync-on-use.sh` | PreToolUse `Bash\|Edit\|Write\|Read` | BLOCKING: the first touch of a `~/repos/<fork>` (path, cwd, or a path in a Bash command; worktrees count as their repo) waits for `gh repo sync` + fetch + ff of the default branch; a failed sync blocks the call |
| `session-ledger.sh` | PostToolUse `Edit\|Write\|Bash` | logs repos touched, files written and git actions to the vault `_recaps/<date>-<sid>.md` (git-ignored) |
| `enforce-prompt.sh` + `classify.sh` | UserPromptSubmit | works out the required skill / read / script per prompt (keyword rows, or `CLASSIFY_URL` backend) |
| `context-diff.sh` | SessionStart | shows CLAUDE.md / MEMORY.md lines changed since the last session |
| `housekeeping-check.sh` | SessionStart | "HOUSEKEEPING DUE" when PENDING.md `last-housekeeping` is 7+ days old or it's the end of the week |
| `staged-updates.sh` | SessionStart (Termux only) | lists staged skill updates still pending in the vault `skill-updates/PENDING.md` (a `## <name> -> ...` heading without `[installed`) and a one-line inventory of the Termux skills and installed plugins to attach (no network). The Stop gate asks until each is installed and its heading marked `[installed <date>]`, or the operator types `#staged-defer` (that session only, asked once per turn) |
| `ship-session.sh` | SessionEnd | ships only repos this session touched, only files changed this session: branch → commit (gitleaks) → PR → auto-merge; writes `## Shipped` into the recap. Also: ships session worktrees the ledger never listed (`~/repos/.wt-*`, repos with 2+ worktrees); copies the recap to `NvAEx-Recaps/recaps/<repo>/` for every repo touched (own branch, shipped last); a repo with no origin is reported `NO REMOTE, NOT SHIPPED` |
| `vault-ship.sh` (+ `~/bin/vault-ship`) | wrap-up (from ship-session) or by hand | uploads the vault (replaces GitSync's upload): merges what GitHub has, commits, pushes `vault-sync`, opens the PR to `main` with auto-merge. `--dry-run` previews. Never switches branches; stops on empty git objects; restores files emptied by failed writes |
| `archive-scratchpad.sh` | SessionEnd / PreCompact | copies the session scratchpad to `~/.claude/scratchpad-archive/` |
| `stop-gate.sh` (H1 Stop) | Stop | two named checklists. Opening (until the operator checks in): O1 RESUME read, O2 repo AGENTS.md read, O3 PENDING.md read, O4 plan posted (`resume-item plan`), O5 task-observer loaded + scan (when the vault's skill-observations exists), O6 operator check-in. Wrap-up (`/wrapup`): W1 every START HERE item `/ok`'d after `resume-item N done` or `/defer`'d (deferred items in the repo's or the vault's PENDING.md; carried-over items need `/defer N why:`), W2 observer events logged/dismissed + weekly review + parked branches, W3 per-repo MEMORY.md/AGENTS.md/no CLAUDE.md, W4 PENDING changed, W5 RESUME rewritten AND dated today (repo and vault), W6 session work committed, vault with uncommitted changes shipped by `vault-ship`, CI + required checks on repos with something to ship, W7 change review `/ok push`, W8 staged skill updates. `#skip-enforce` / `#staged-defer` count only in prompts the operator typed, never inside a subagent hand-back. Operator-only items block once, then yield. In the cloud a check that needs the phone is reported as a NOTE, never dropped |
| `absence-gate.sh` | Stop | a final answer saying something is "not found / doesn't exist / undefined / no such X" needs a search in the same turn (Bash grep/find/rg/ls/gh search/gh api/gh repo/git log, Grep, Glob, WebSearch, MCP search/hf_fs). Lines that name their probes ("not found by ...", "searched", "probes:", "Where I looked") pass. Blocks once (`stop_hook_active` allows); fails open, logged to `~/.claude/state/absence-gate.log`. Decision 56, obs 0034. Live install (manual): copy it to `~/.claude/hooks/` and add its entry from `settings.hooks.json` to the first `Stop` group in `~/.claude/settings.json`. |
| `carryover.sh` (H9, used by the Stop gate) | Stop, `/wrapup` | a START HERE item an earlier session left unfinished can't be deferred again without the operator's reason (`/defer N why: <reason>`); otherwise it has to be finished. Ledger: `~/.claude/state/carryover/<sid>.tsv`. Items match by title (first 40 letters/digits), so keep titles when rewriting RESUME. `carryover.sh list <snapshot>` shows carried items |
| `subagent-stop-gate.sh` | SubagentStop | a subagent whose spawn prompt names `~/.claude/session-work/<date>/agent-<topic>.md` can't finish while that file is missing or a `- [ ]` step in `## Plan` isn't listed under `## Blocked`. Blocks once (`stop_hook_active` allows). Feedback goes to the subagent only |
| `observe-event.sh` (+ `observe-corrections.txt`, `~/bin/observe-dismiss`) | SessionStart `compact`, PostToolUseFailure, PermissionDenied, UserPromptSubmit | compaction: clears `satisfied-<sid>.tsv` and records it, so the Stop gate wants task-observer loaded and a new session-start scan. | `run-hook.sh` | (launcher) | aesop-xi `.claude/settings.json` registers every hook above through this, so any session started in aesop-xi gets them on any device, cloud sessions included: nothing stands down. Operator override for enforcement (user-typed only): `#skip-enforce` in a prompt (logged). A `#skip-enforce` or `#staged-defer` that arrives inside a subagent hand-back is ignored.

Tests: `hooks/tests/*.test.sh` and `test-*.sh` (CI runs them all; locally they need a bash at the Termux shebang path and `gitleaks` on PATH for the two ship suites).

## Git workflow (always on)
1. Repo current with main before any edit/commit (`branch-current-gate.sh`; H2 sync-on-use syncs forks).
2. Every change logged as it happens (H3 session ledger → vault `_recaps/`).
3. Secrets scanned on every commit and push (H5 gitleaks).
4. Ship: push → PR → auto-merge (squash) → branch deleted after MERGED (H4 ship-session), on "push now" or `/wrapup`.
5. Keep a branch: type `#keep-branch <name>` → ship pushes a `saved/<name>` copy before merging.
6. `/wrapup` can't finish with uncommitted session work in any repo (Stop gate).

## Session start / end (operator check-off)
1. RESUME read → snapshot + fingerprint saved (resume-gate).
2. Agent posts the START HERE plan (each item, what it will do, tools/skills), runs `resume-item plan`, ends the turn.
3. Operator replies `/ok 1,3`, `/ok 1-4`, `/ok all`, `/defer 2`, `/reject 2`, `/write 2 <changed instruction>` or `/write <new item>` (or the `#` forms) to the plan. `/write` puts the operator's own words into the snapshot item (the agent follows that text, not the old item) and records them in `state/written-<sid>.tsv`. At the end of the session a bare `/ok` confirms everything as marked: done → confirmed, blocked → deferred. Until then: no changes (checkin-gate).
4. Agent marks finished items `resume-item <n> done "<evidence>"`; they count only after the operator's `#ok <n>`. `#reject <n>` clears a proposal.
5. `/wrapup`: every item must be operator-confirmed done or deferred (deferred ones in PENDING.md), RESUME rewritten, session work committed.
6. An item already carried over from an earlier session can't be deferred again with a plain `/defer N`: finish it, or type `/defer N why: <reason>` (H9).
